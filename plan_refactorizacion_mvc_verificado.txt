1. Actualizar el Modelo (app/Models/AsignacionTurno.php):
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Builder;

class AsignacionTurno extends Model
{
    public function scopeBuscarPorConductor(Builder $query, string $criterio): Builder
    {
        return $query->whereHas('conductor', function ($q) use ($criterio) {
            $q->where('nombre', 'like', "%{$criterio}%")
              ->orWhere('apellido', 'like', "%{$criterio}%");
        })->orWhere('fecha', 'like', "%{$criterio}%");
    }

    public function estaActivo(): bool
    {
        return !in_array($this->estado, ['cancelado', 'completado']);
    }
}

FASE 6 (NUEVA / CORREGIDA): PARAMETRIZACIÓN = ELIMINACIÓN LÓGICA POR SERVICE,
NO "TRANSACCIONES" POR CARPETA
-------------------------------------------------------------------------------
[CORRECCIÓN DE ENFOQUE: la primera versión de esta fase proponía separar
"Transacciones" de "Parametrización" solo con carpetas/prefijos de ruta.
Se corrige el enfoque: lo que en realidad distingue a los módulos de
catálogo/parametrización es que su `destroy()` NO debe borrar el registro,
sino hacer una ELIMINACIÓN LÓGICA (estado = inactivo). Para la única
entidad transaccional real del sistema (AsignacionTurno, que registra un
hecho fechado: conductor + micro + turno + ruta en una fecha concreta) se
usa una capa de SERVICES (app/Services/), que es el patrón estándar de
Laravel para encapsular reglas de negocio transaccionales fuera del
controlador — en vez de simplemente nombrar una carpeta "Transacciones".

VERIFICACIÓN de eliminación lógica, módulo por módulo (destroy() actual):
  - ConductorController::destroy   -> update(['estado' => 'inactivo'])  OK (lógica)
  - MicroController::destroy       -> update(['estado' => 'inactivo'])  OK (lógica)
  - InternoController::destroy     -> update(['estado' => 'inactivo'])  OK (lógica)
  - TurnoController::destroy       -> update(['estado' => 'inactivo'])  OK (lógica)
  - ParadaController::destroy      -> update(['estado' => 'inactivo'])  OK (lógica)
  - DueñoController::destroy       -> update(['estado' => 'inactivo'])  OK (lógica)
  - RutaController::destroy        -> ->delete()  *** INCONSISTENTE: borrado físico ***
  - RutaParadaController::destroy  -> ->delete()  *** INCONSISTENTE: borrado físico ***
  - AsignacionTurnoController::destroy -> update(['estado' => 'cancelado']) (correcto
    para una transacción: no se "borra" un hecho histórico, se cancela)

Es decir: 7 de 9 módulos ya aplican eliminación lógica de forma consistente;
Ruta y RutaParada rompen el patrón con `delete()` físico y deben corregirse
para no perder integridad referencial con Turno/RutaParada/parada_ruta.]

1. Estandarizar la eliminación lógica de PARAMETRIZACIÓN en un solo lugar

   Crear un trait reutilizable en app/Models/Concerns/TieneEstadoLogico.php:
<?php

namespace App\Models\Concerns;

trait TieneEstadoLogico
{
    public function desactivar(): bool
    {
        return $this->update(['estado' => 'inactivo']);
    }

    public function activar(): bool
    {
        return $this->update(['estado' => 'activo']);
    }
}

   y RutaParada:

   - RutaController::destroy()      -> cambiar `Ruta::findOrFail($id)->delete();`
     por `Ruta::findOrFail($id)->desactivar();`

2. Crear la capa de Services para la lógica TRANSACCIONAL
   (app/Services/AsignacionTurnoService.php). Aquí sí aplica el patrón de
   Service porque AsignacionTurno no es un catálogo: cada registro es un
   hecho fechado con reglas de negocio propias (validar que el turno esté
   activo, evitar choques de conductor/micro en la misma fecha y turno,
   registrar horas de salida/llegada, cancelar en vez de borrar):
<?php

namespace App\Services;

use App\Models\AsignacionTurno;
use App\Models\Turno;
use Illuminate\Validation\ValidationException;

class AsignacionTurnoService
{
    public function crear(array $datos): AsignacionTurno
    {
        $this->validarTurnoActivo($datos['turno_id']);

        return AsignacionTurno::create($datos);
    }

    public function actualizar(AsignacionTurno $asignacion, array $datos): AsignacionTurno
    {
        $this->validarTurnoActivo($datos['turno_id']);

        $asignacion->update($datos);

        return $asignacion;
    }

    public function cancelar(AsignacionTurno $asignacion): AsignacionTurno
    {
        // Eliminación lógica de una transacción: se cancela, no se borra
        // el hecho histórico.
        $asignacion->update(['estado' => 'cancelado']);

        return $asignacion;
    }

    protected function validarTurnoActivo(int $turnoId): void
    {
        $turno = Turno::findOrFail($turnoId);

        if ($turno->estado !== 'activo') {
            throw ValidationException::withMessages([
                'turno_id' => 'El turno seleccionado está inactivo.',
            ]);
        }
    }
}
